# dsh-memory-context-lab

按 **DSH 会话** 启用的上下文降温插件。把**已执行完的操作**（助手发出的工具调用连同参数、以及对应的工具结果）整体沉入一个隔离冷库，用一条极小的回执替换掉这段历史——在不丢任何工具能力的前提下，把上下文输入降下来、把前缀缓存命中率抬上去。

> 适用对象：[DeepSeek Harness (DSH)](https://github.com/DeepSeek-ai/DeepSeek-Harness) 桌面端插件体系。当前版本 **0.6.0**，变化见 [CHANGELOG.md](CHANGELOG.md)。

## 它解决什么问题

长 agentic 会话是「一条用户消息 + 几十次工具调用」。这些调用参数与结果会迅速把上下文窗口占满，挤占模型真正需要用来推理的空间；更糟的是，频繁增长的输入会反复**打穿前缀缓存**，让每一轮都按未命中价重算。

本插件的做法是：**归档**而不是删除。已完成的操作被写进一个每会话隔离的冷库，活动面只留一条小回执。需要时随时 `restore` 原字节、可审计、可回放。归档后工具照常可用、照常调用。

## 核心特性

- **按会话启用** — `/memory-lab on` 只影响当前会话，不污染其它会话；同时抑制本会话对真实记忆库的自动读写。
- **攒批归档** — 保留最近 N 个操作原文，更旧的攒够 `batch`（默认 10）个才提交一批。批次数才是缓存重算的代价来源，攒批能把成本压到极低（真实 1M 窗口会话实测：攒 10 个约为基线的 **0.16×**，攒 1 个约 0.62×）。
- **单一触发线** — 保留最近 N 个操作是唯一触发线，与占用率无关：更旧的操作攒够 `batch` 个就归档。0.5.0 起删除了从未触发的占用率安全网，上下文上限改由宿主自己的自动压缩兜底。
- **当前轮围栏** — 最后一条助手消息及其操作在当前批次被挡住（它们携带的证据模型可能还在发送），下一个用户消息落面后自动放开；防止把模型刚说过的话从可见上下文里抽走。
- **单批释放上限** — 一批最多释放约 65536 token，超出的候选留到下一批并在报告里标注，避免大量证据在一步内同时退出上下文。
- **命中回注** — 归档要点按相关度回注到上下文尾部，模型仍能「记得」被归档操作干了什么。装包受预算约束，去重只作用于**当前仍可见**的证据：已退出上下文、之后又需要的证据可以再次装包。
- **可逆可审计** — 走宿主自己的表层替换（与官方压缩同一机制），原始事件仍在 append-only 日志里；`restore` 按原字节写回。
- **工具集恒定** — 从不增删模型可见工具，避免作废整段前缀缓存。
- **失败关闭** — 冷库不可用、回读校验不符、或会超出模型窗口时，一律保留原文并报告原因，不改写任何会话内容。
- **状态损坏不误判** — 状态文件读不出来时，区分「文件不存在」与「文件损坏」：损坏的会话停止干预并显式报告，而不是被当成「从未启用」，也不会顺手清理冷库。

## 安装

```text
# 作为 DSH bundle 安装（desktop profile）
plugin_manager install_bundle <本仓库目录>

# 改动宿主侧源码后需重启 DSH Desktop；只改 src/client.js 时刷新页面即可
```

依赖：已核验 `dsh-memory`（peer `@furongjun1999/dsh-memory@0.8.1`）。冷库不可用不会阻止启用，归档/回注会在真正尝试时失败关闭。

## 使用

```text
/memory-lab on                       在当前会话启用降温
/memory-lab off                      停用并回到正常：恢复原文、解除抑制、清除插件数据
/memory-lab status                   保留量、批量阈值、归档数、占用率与前缀缓存命中
/memory-lab set retain 10            保留最近 N 个操作原文（唯一触发线）
/memory-lab set batch 10             保留窗口外攒够 N 个提交一批（越大越省缓存重算）
/memory-lab set auto on|off          自动降温（默认开）
/memory-lab set recall on|off        命中回注（默认开）
/memory-lab set autorestore on|off   停用时恢复原文并清数据（默认开）
/memory-lab preset                   列出全局默认与全部预设
/memory-lab preset <名称|id|reset>   应用预设；reset 回全局默认
/memory-lab now                      立即测量并归档一批
/memory-lab dry-run                  只估算与选候选，零副作用
/memory-lab restore                  恢复操作原文
/memory-lab clean                    删除本会话隔离数据（有未恢复回执时拒绝）
/memory-lab help                     以上全部
```

图形入口：composer 工具行权限控件右侧的「降温」触发器，点开是同一套设置与动作，顶部可切换预设。全局默认与预设列表在 设置 → 组件 → 「记忆上下文」行维护（可新增、改名、调值、删除），保存立即生效，已启用降温的会话不受影响。

`off` 与归档共用一条清理路径：先恢复原文，再解除抑制，最后删除该会话隔离目录（顺序不可颠倒）。仍有已归档操作没能恢复时 `off` 不会删除，而是给出两条出路：`restore` 后再 `off`，或 `clean confirm delete-session` 直接丢弃冷库。

## 安全边界

- 归档前先把正文写进冷库并**回读校验指纹**；写入失败、回读缺失/被裁剪、或指纹不符，一律保留原文并报出具体阶段。
- 正文大于单个冷节点可回读上限时**按码点分块**，每块独立校验、拼接后再校验整篇指纹，大 `read`/`edit` 同样可归档。
- 归档正文含工具参数与结果全文，恢复时按原字节写回。
- 回执文本只由稳定标识符构成，不含时间戳与动态统计，重复运行逐字节一致，不扰动缓存。
- 冷库删除只能删插件自有目录，拒绝含链接的路径；DSH 的会话日志与命令审计不由插件改写。
- 恢复失败与账本不一致都停在安全侧：冷节点缺失或校验不符时不清理、不改写，失败原因持久化；事务记录先于投影替换落盘，重试沿用同一冷节点 ID。

## 已知限制

- 状态与报告里的 token 数字是**容量估算**（已扣除回执成本），不是已节省的实际输入或费用。真实收益需要同检查点基线对比，且必须计入每批替换引发的前缀缓存失效；在缓存命中率很高的路由上收益可能为负。
- 冷库与抑制层绑定固定版 `dsh-memory@0.8.1`（补丁其私有接口）；灵枢升级后会显式失败，不静默降级到正式灵枢根。
- 召回是模糊检索，不保证只返回强相关条目；装包按预算与「当前是否可见」去重，不设相关性硬阈值。
- 只处理完整操作节点：不摘要助手的自然语言回复，不做跨会话批量降温。
