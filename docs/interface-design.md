## 总图：四个端口

整个插件由四个端口（接口）连在一起。每个端口是一个约定：**只要满足这个约定，任何实现都能插入**。

```
┌──────────────────────────────────────────────────────────┐
│              引擎（已有的 apply-engine + v2/runtime）      │
│              不改动，只通过端口使用下面的能力               │
└──────┬───────────────┬───────────────┬──────────────────┘
       │               │               │
┌──────▼──────┐  ┌────▼──────┐  ┌────▼──────────┐
│ 端口一       │  │ 端口二     │  │ 端口三          │
│ 冷库端口     │  │ 检索端口   │  │ 客户端端口       │
│ 存取原文     │  │ 找回记忆   │  │ 读写一体         │
└──────┬──────┘  └────┬──────┘  └────┬──────────┘
       │               │               │
┌──────▼──────┐  ┌────▼──────┐  ┌────▼──────────┐
│ 冷库实现     │  │ 检索实现    │  │ 客户端实现      │
│ （已有）     │  │ （T1 新增   │  │ （统一 v1/v2）  │
│             │  │  T2 可选）  │  │                │
└─────────────┘  └───────────┘  └────────────────┘
       ↑
┌──────┴──────────────────────────────────────────────────┐
│ 端口四：功能分级配置（控制上面三个端口的行为）                │
└─────────────────────────────────────────────────────────┘
```

## 端口一：冷库端口

**谁用它**：引擎（v1 和 v2 都通过这个端口读写冷库）。
**谁实现它**：`V2SessionStore`（现有实现，不动）。未来如果要换存储引擎（比如换数据库），写一个新的实现就行。

这个端口已经有实现了（`v2/store.mjs` 的 `V2SessionStore`），本节把它的公开方法正式化为端口约定，**不改语义**。

| 方法 | 输入 | 输出 | 做什么 |
|---|---|---|---|
| `stageRecord(txn, draft)` | 事务对象 + 记录草案 | 已暂存的记录 | 把一条记录写进当前事务（内容寻址，不可变） |
| `commitTransaction(txn)` | 事务对象 | 提交结果 | 原子提交事务里的所有暂存记录 |
| `abandonTransaction(txn)` | 事务对象 | 无 | 放弃事务（不留半成品） |
| `readRecord(id, options)` | 记录 ID + 可选的读取上限 | 记录内容 + 完整性 + 是否被截断 | 按 ID 读一条记录，校验内容哈希 |
| `listEntries(options)` | 可选的限制 | 所有记录的目录条目 | 列出本会话的全部记录（只读目录，不读正文） |
| `getEntry(id)` | 记录 ID | 目录条目或空 | 查一条记录的元信息（不读正文） |
| `close()` | 无 | 无 | 释放存储句柄 |

**不变量**（任何实现都必须保证）：

- 每条记录的内容哈希在写入时计算，读取时校验——不一致即报错，不返回可能被篡改的内容
- 写入是原子的：要么全部落盘，要么全部不留痕迹
- 记录不可修改：写入后只能新增，不能覆盖或删除

## 端口二：检索端口

**谁用它**：引擎的检索面（自动回注 + 模型主动查询）。
**谁实现它**：三种检索后端（T0 字面是内置的，T1 本地词法和 T2 灵枢是可插拔的）。

这个端口的契约已经在 `v2/retrieval.mjs` 的 `assertBackendContract` 里定义了。本节补上两个可选方法，并把语义写清楚。

| 方法 | 输入 | 输出 | 做什么 |
|---|---|---|---|
| `name` | 无（属性） | 非空字符串 | 后端的名字。换名字 = 索引作废重建 |
| `capabilities` | 无（属性） | 能力自述对象 | 告诉调用方我能做什么、不能做什么（不许夸大） |
| `index(records)` | 一批待索引的记录（每条带 ≤8KB 有界摘录） | 索引结果（含被拒收的条目） | 把记录加进索引。**没写进去的要如实报 skipped** |
| `query(text, options)` | 查询文本 + 条数上限 | 记录 ID 数组 | 按文本查记录。**只返回 ID，不返回正文** |
| `ping()` *(可选)* | 无 | 是否就绪 | 装配期探测：灵枢后端用它确认子进程握手成功 |
| `dispose()` *(可选)* | 无 | 无 | 释放后端持有的资源（如子进程） |

**三种实现的分工**：

| 实现 | 名字 | 依赖 | 什么时候生效 |
|---|---|---|---|
| T0 字面 | 内置 | 无 | 恒在 |
| T1 本地词法 | `local-lexical-v1` | 无（纯 Node） | 默认 |
| T2 灵枢 | `lingshu-mdcg-receipt` | dsh-memory + python | 探测到且握手成功时优先 |

**选择规则**：装配期一次决定，运行期不换。如果用户显式指定了后端但不可用，启动时报错（不静默降级）。

## 端口三：客户端端口

**谁用它**：v1 引擎（`apply-engine.mjs`）和 v2 引擎（`v2/runtime.mjs`）。
**谁实现它**：`v2/client-adapter.mjs` 的 `createV2ClientFactory` 产出的客户端（已有实现，需补一个方法）。

这是两个引擎共用的唯一读写入口。

| 方法 | 输入 | 输出 | 做什么 |
|---|---|---|---|
| `rememberArchived(args)` | nodeId + text + range + tools + callIds + contentHash + chunk 信息 | 写入结果（成功/复用/冲突） | 把一段原文写入冷库（写入即不可变，同 ID 不同内容拒收） |
| `getNode(nodeId)` | 节点 ID | 三态：完整正文 / 截断 / 不存在 | 按节点 ID 回读原文 |
| `recall(query, signal, limit)` | 查询文本 + 取消信号 + 条数 | 检索命中列表 | 从冷库里找回相关记录（走检索端口） |
| `close()` | 无 | 无 | 释放存储句柄 |
| `dispose()` | 无 | 无 | 彻底清理（会话结束时调用） |

**三态回读的约定**（`getNode` 的返回值必须严格区分三种情况）：

| 返回 | 含义 | 调用方怎么处理 |
|---|---|---|
| `{ ok: true, content, id }` | 完整正文 | 可以安全使用 |
| `{ ok: false, error: 'truncated', nextOffset }` | 被截断了，不是完整正文 | **绝不能**当完整正文用（哈希校验会失败） |
| `{ ok: false, error: 'not_found' }` | 不存在 | 如实报告缺失，不静默跳过 |

## 端口四：功能分级配置

用户通过配置选择启用到哪一级。每级向下包含。

| 级 | 名称 | 打开的能力 | 对应配置 |
|---|---|---|---|
| 恒开 | 不可遗忘层 | 保护集、计划全文、回执凭证永远留在工作台上 | 不可配置 |
| L0 | 基线 | 宿主原生（无降温）——参照点 | 不启用插件 |
| L1 | 降温 | 归档 + 回执替换 | `/memory-lab on` 或 `/memory-lab2 on` |
| L2 | 自动回注 | 命中回注（T0 字面检索） | `set auto on` + `set recall on` |
| L3 | 词法检索 | T1 本地词法索引 | 默认启用 |
| L4 | 全历史记忆 | fullhistory（原始历史全存按需读取） | `set fullhistory on` |
| L5 | 灵枢后端 | T2 灵枢检索 | 装 dsh-memory + 握手成功 |
| 附加 | 计划先行 | 新会话自动进入计划模式 | `set planfirst on` |

**规则**：向下包含；恒开层不受分级影响；切换只在批次边界生效。

## 新增模块：验证跟踪

现在缺一块：**工具结果对应的文件后来被改了吗？** 如果改了，之前读到的内容就过时了。需要一个跟踪机制。

| 方法 | 输入 | 输出 | 做什么 |
|---|---|---|---|
| `check(recordId)` | 记录 ID | `'valid'` 或 `'stale'` | 检查这条记录引用的文件当前是否还和读取时一致 |
| `markStale(recordId, reason)` | 记录 ID + 原因 | 无 | 标记一条记录为过时（不删除，只是标记） |

实现方式：利用 `working-state.mjs` 已有的 `FINGERPRINT_VERDICTS` 和 `fingerprintOf` —— 记录读取时记下文件的指纹，`check` 时重新计算指纹并对比。指纹不同 = 文件变了 = 记录过时。

## 错误处理约定

全插件统一用 `EngineV2Error`（`v2/errors.mjs`），每个错误带一个 `code` 字段。已有的错误码不重复列举，新增的：

| 错误码 | 什么时候抛 |
|---|---|
| `EBACKENDUNAVAILABLE` | 用户显式指定的检索后端不可用（启动期） |
| `EBACKENDPINGFAIL` | T2 灵枢后端握手失败 |
| `EVERIFICATIONSTALE` | 工具结果对应的文件已被修改 |

**约定**：所有错误都带中文描述和 `code` 字段；不吞错误、不静默降级为成功；降级必须如实标注降级原因。

---

## 测试约定

每个端口至少要测：

1. **契约符合**：实现是否满足端口约定（方法齐、签名对、语义正）
2. **不变量**：端口承诺的「绝对不发生」的事（如内容哈希不匹配必须报错）
3. **边界**：空输入、超长输入、非法输入
4. **变异**：把实现改坏一个关键点，确认测试会变红
